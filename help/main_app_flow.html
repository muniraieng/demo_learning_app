Main App Flow

App Start to Screen — Complete Bootstrap Flow

Tags

GetX Riverpod CLEAN MVVM ScreenUtil

1. Yeh Flow Kya Hai?

Yeh flow batata hai app start hone se screen render hone tak ka complete path. main.dart me sab kuch wire hota hai — DI, navigation, aur state management setup.

2. Files Involved

  • lib/main.dart — App entry point + DI bootstrap
  • lib/background/sync_worker.dart — WorkManager background sync
  • lib/core/storage/secure_token_storage.dart — Token check
  • lib/presentation/screens/login_screen.dart — Login screen
  • lib/presentation/screens/course_dashboard_screen.dart — Dashboard screen

3. Complete Flow (Step by Step)

Step 1: main() call hota hai │ WidgetsFlutterBinding.ensureInitialized() │ SyncWorker.register() — WorkManager init │ ▼ Step 2: Dependencies create hoti hain │ AppDatabase() — Drift SQLite │ NetworkInfoImpl() — Connectivity check │ SecureTokenStorage() — Token storage │ AuthLocalDataSource(tokenStorage) │ CourseLocalDataSource(db) │ CourseRemoteDataSource() │ ▼ Step 3: Repositories create hoti hain │ AuthRepositoryImpl(authLocal) │ CourseRepositoryImpl(remote, local, networkInfo) │ ▼ Step 4: UseCases create hote hain │ LoginUseCase(authRepository) │ GetCoursesUseCase(courseRepository) │ ▼ Step 5: GetX DI me register hota hai │ Get.put(tokenStorage) │ Get.put(loginUseCase) │ Get.put(getCoursesUseCase) │ Get.put(LoginViewModel(loginUseCase)) │ Get.put(CourseDashboardViewModel(getCoursesUseCase)) │ ▼ Step 6: runApp() call hota hai │ ProviderScope(child: LearningDashboardApp()) │ ScreenUtilInit → GetMaterialApp │ home: _RootGate() │ ▼ Step 7: _RootGate check karta hai │ Get.find().readToken() │ ├── Token hai → CourseDashboardScreen() │ (User already logged in) │ └── Token nahi → LoginScreen() (User ko login karna hoga)

4. DI Bootstrap (GetX)

main.dart me GetX ka use karke dependencies inject hoti hain:

Get.put(tokenStorage) // SecureTokenStorage Get.put(loginUseCase) // LoginUseCase Get.put(getCoursesUseCase) // GetCoursesUseCase Get.put(LoginViewModel(loginUseCase)) // LoginViewModel Get.put(CourseDashboardViewModel(getCoursesUseCase)) // DashboardVM // Baad me koi bhi screen chahe toh: Get.find() // Auto-mil jayega

5. Riverpod Provider Graph (Detail Screen ke liye)

Detail screen ke liye Riverpod providers bhi define hain:

appDatabaseProvider └─ AppDatabase() courseLocalDataSourceProvider └─ CourseLocalDataSource(db) courseRemoteDataSourceProvider └─ CourseRemoteDataSource() networkInfoProvider └─ NetworkInfoImpl() courseRepositoryProvider └─ CourseRepositoryImpl(remote, local, networkInfo) getCourseDetailUseCaseProvider └─ GetCourseDetailUseCase(repository) markLessonCompletedUseCaseProvider └─ MarkLessonCompletedUseCase(repository) courseDetailViewModelProvider (Family) └─ CourseDetailViewModel(courseId)

6. ScreenUtilInit Ka Role

flutter_screenutil responsive UI ke liye use hota hai. Design size 375x812 (iPhone X) set hai:

ScreenUtilInit( designSize: Size(375, 812), minTextAdapt: true, splitScreenMode: true, builder: (context, child) => GetMaterialApp(...) ) // Usage: EdgeInsets.all(24.w) // .w = width responsive EdgeInsets.all(16.h) // .h = height responsive fontSize: 14.sp // .sp = font responsive borderRadius: 12.r // .r = radius responsive

7. _RootGate Ka Role

_RootGate ek StatefulWidget hai jo decide karta hai kis screen pe jana hai:

_RootGateState._check() │ ├── Token mil gaya → _hasSession = true │ → CourseDashboardScreen() │ └── Token nahi mila → _hasSession = false → LoginScreen() // Loading state: _resolved = false → CircularProgressIndicator _resolved = true → Screen show
