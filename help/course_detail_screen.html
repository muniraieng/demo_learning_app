Course Detail Screen

Kaise kaam karta hai — Step by Step Flow

Tags

Riverpod Notifier CLEAN MVVM Offline-First ScreenUtil

1. Yeh Screen Kya Karta Hai?

Detail Screen ek specific course ke saare lessons dikhta hai. User yahan se lessons ko complete kar sakta hai. Progress automatically update hota hai. Screen pe RefreshIndicator bhi hai pull-to-refresh ke liye.

2. Files Involved

  • lib/presentation/screens/course_detail_screen.dart — UI (ConsumerWidget)
  • lib/presentation/viewmodels/course_detail_viewmodel.dart — State (Riverpod Notifier)
  • lib/domain/usecases/get_course_detail_usecase.dart — Detail fetch logic
  • lib/domain/usecases/mark_lesson_completed_usecase.dart — Lesson complete logic
  • lib/data/repositories/course_repository_impl.dart — Data + Offline
  • lib/database/app_database.dart — Drift SQLite

3. Complete Flow (Step by Step)

Step 1: Dashboard se course tap kiya │ Get.to(() => CourseDetailScreen(courseId: c.id)) │ ▼ Step 2: Screen khulta hai │ ConsumerWidget ref.watch(provider) karta hai │ courseDetailViewModelProvider(courseId) │ ▼ Step 3: Provider create hota hai │ CourseDetailViewModel(courseId) build call │ state = CourseDetailState(isLoading: true) │ Future.microtask(load) schedule hota hai │ ▼ Step 4: Load data │ GetCourseDetailUseCase.call(courseId) │ → Repository se course detail aata hai │ → Drift DB se read hota hai (single source of truth) │ ▼ Step 5: State update │ state = CourseDetailState( │ isLoading: false, │ course: course, │ failure: null │ ) │ UI rebuild hota hai │ ▼ Step 6: User lesson complete karta hai │ "Mark complete" button tap │ → vm.completeLesson(lessonId) │ → MarkLessonCompletedUseCase.call() │ → Drift DB me update │ → Progress recalculate │ → State update → UI rebuild

4. Riverpod Provider Graph

Yeh screen Riverpod use karta hai (GetX nahi). Provider graph aisa dikhta hai:

appDatabaseProvider └─ AppDatabase() (Drift DB) courseLocalDataSourceProvider └─ CourseLocalDataSource(db) courseRemoteDataSourceProvider └─ CourseRemoteDataSource() networkInfoProvider └─ NetworkInfoImpl() courseRepositoryProvider └─ CourseRepositoryImpl(remote, local, networkInfo) getCourseDetailUseCaseProvider └─ GetCourseDetailUseCase(repository) markLessonCompletedUseCaseProvider └─ MarkLessonCompletedUseCase(repository) courseDetailViewModelProvider (Family) └─ CourseDetailViewModel(courseId)

5. Riverpod vs GetX — Farq Kya Hai?

GetX (Login + Dashboard): - GetxController + .obs variables - Obx() widget se reactive UI - Get.put() se dependency inject - Simple aur quick Riverpod (Detail Screen): - AutoDisposeFamilyNotifier + State class - ref.watch() se reactive UI - Provider graph se dependency inject - Type-safe aur test-friendly - autoDispose = auto cleanup

6. Lesson Complete Kaise Kaam Karta Hai?

User "Mark complete" tap karta hai │ ▼ vm.completeLesson(lessonId) │ ▼ MarkLessonCompletedUseCase.call(courseId, lessonId) │ ▼ CourseRepositoryImpl.markLessonCompleted() │ ▼ Drift DB me update: - Course row find karo (courseId se) - Lessons JSON parse karo - Specific lesson ko complete mark karo - Progress recalculate: (done/total) * 100 - Updated JSON save karo │ ▼ getCourseDetail() se updated course return │ ▼ State update → UI rebuild - Check icon green ho jata hai - "Completed" text dikhta hai - Progress bar update hota hai

8. autoDispose Ka Matlab?

autoDispose ka matlab hai jab user screen se bahar jata hai, toh provider apne aap cleanup ho jata hai. Memory leak nahi hota.

9. Family Provider Ka Matlab?

Family ka matlab hai ek hi provider se multiple instances bana sakte hain. Har course ka apna alag ViewModel hota hai:

courseDetailViewModelProvider(1) → Course 1 ka ViewModel courseDetailViewModelProvider(2) → Course 2 ka ViewModel courseDetailViewModelProvider(3) → Course 3 ka ViewModel
